提示工程，也称为上下文提示，指的是如何与大型语言模型（LLM）沟通以引导其行为，从而获得预期结果的方法，而无需更新模型权重。它是一门经验科学，不同模型对提示工程方法的效果差异很大，因此需要进行大量实验和探索启发式方法。

本文仅专注于自回归语言模型的提示工程，因此不涉及完形填测试、图像生成或多模态模型。其核心目标是实现对齐和模型可控性。可以参考我关于可控文本生成的上一篇博文。

[我的个人观点] 我认为，有些提示工程论文不值得写满8页，因为那些技巧一两句话就能说清楚，其余部分全是基准测试。一个易于使用且共享的基准测试基础设施对社区会更有益。迭代提示或使用外部工具的设置并不简单，要让整个研究社区都采用它也非易事。

基础提示法#

零样本学习和少样本学习是两种最基础的提示模型方法，由许多大型语言模型论文开创，并常用于基准测试模型性能。

零样本学习就是直接将任务文本输入模型并请求结果。

少样本#

少样本学习会为目标任务提供一组高质量的示例，每个示例都包含输入和期望的输出。由于模型首先看到好的示例，它能更好地理解人类的意图以及所需答案的标准。因此，少样本学习通常比零样本学习效果更好。然而，它的代价是消耗更多token，当输入和输出文本较长时可能会遇到上下文长度限制。

许多研究探讨了如何构建上下文示例以最大化性能，并观察到提示格式、训练示例的选择以及示例的顺序会导致性能的巨大差异，从接近随机猜测到接近最先进水平。

Zhao 等人 (2021) 研究了少样本分类的情况，并提出几种大语言模型（他们在实验中使用的是 GPT-3）的偏差导致了这种高方差：(1) 如果示例中标签分布不均衡，则存在多数标签偏差；(2) 近期偏差指的是模型可能重复末尾标签的倾向；(3) 常见词偏差表明大语言模型倾向于生成常见词而非罕见词。为了克服这些偏差，他们提出了一种方法，当输入字符串为 N/A 时，将模型输出的标签概率校准为均匀分布。

示例选择技巧#

  • 在嵌入空间中使用 $k$-NN 聚类选择与测试示例语义相似的示例 (Liu 等人, 2021)

  • 为了选择多样且具有代表性的示例集，Su et al. (2022) 提出了一种基于图的方法：(1) 首先，根据样本之间的嵌入（例如通过 SBERT 或 其他 嵌入 模型）的余弦相似度构建一个有向图 $G=(V, E)$，其中每个节点指向其 $k$ 个最近邻；(2) 从一组已选样本 $\mathcal{L}=\emptyset$ 和一组剩余样本 $\mathcal{U}$ 开始。每个样本 $u \in \mathcal{U}$ 的评分为 $$ \text{score}(u) = \sum_{v \in \{v \mid (u, v) \in E, v\in \mathcal{U}\}} s(v)\quad\text{其中 }s(v)=\rho^{- \vert \{\ell \in \mathcal{L} \vert (v, \ell)\in E \}\vert},\quad\rho > 1 $$ 这样，如果 $v$ 的许多邻居已被选中，则 $s(v)$ 会较低，因此该评分机制鼓励选择多样化的样本。

  • Rubin et al. (2022) 提出通过针对特定训练数据的对比学习来训练嵌入，用于上下文学习中的样本选择。对于每个训练对 $(x, y)$，可以通过语言模型（LM）分配的条件概率来衡量一个示例 $e_i$（格式化的输入-输出对）的质量：$\text{score}(e_i) = P_\text{LM}(y \mid e_i, x)$。我们可以为每个训练对识别出评分最高和最低的 top-$k$ 和 bottom-$k$ 示例，作为候选的正负样本集，并用于对比学习。

  • 一些研究人员尝试使用 Q-Learning 进行样本选择。（Zhang et al. 2022）

  • 受基于不确定性的 主动学习 的启发，Diao 等人 (2023) 建议识别在多次采样试验中存在较大分歧或熵值的示例。然后对这些示例进行标注，用于少样本提示中。

示例排序技巧#

  • 一个通用建议是保持示例选择的多样性，使其与测试样本相关，并采用随机顺序，以避免多数标签偏差和近期偏差。
  • 增加模型规模或包含更多训练示例并不能减少上下文示例不同排列之间的方差。相同的顺序可能对某个模型效果很好，但对另一个模型却可能效果很差。当验证集有限时，可以考虑选择一种顺序，使得模型不会产生极度不平衡的预测或对自己的预测过度自信。（Lu 等人 2022）

指令提示#

在提示中展示少样本示例的目的是向模型解释我们的意图；换句话说，通过演示的形式向模型描述任务指令。然而，由于上下文长度有限，少样本方式在 token 使用上可能成本较高，并且限制了输入长度。那么，为什么不直接给出指令呢？

指令微调模型（例如 InstructGPT、natural instruction）使用高质量的（任务指令、输入、真实输出）元组对预训练模型进行微调，以使语言模型能更好地理解用户意图并遵循指令。RLHF（基于人类反馈的强化学习）是常用的方法。指令风格微调的好处在于，它能让模型更好地与人类意图保持一致，并大大降低沟通成本。

与指令模型交互时，我们应该详细描述任务要求，力求做到 具体 和 精确，避免使用“不要做什么”这样的表述，而是明确指出要做什么。

自一致性采样#

自一致性采样 (Wang et al. 2022a) 指的是在温度 > 0 的情况下采样多个输出，然后从这些候选结果中选择最佳的一个。选择最佳候选的标准可能因任务而异。一个通用的解决方案是采用多数投票。对于那些易于验证的任务，比如有单元测试的编程问题，我们可以直接运行代码并通过单元测试来验证正确性。

思维链 (CoT)#

思维链提示（Chain-of-thought prompting） (Wei et al. 2022) 通过生成一系列短句来逐步描述推理逻辑，这些短句被称为推理链或理由，最终引导出最终答案。CoT 在复杂推理任务上的优势更为明显，尤其是在使用大型模型（例如参数量超过 500 亿的模型）时。简单任务从 CoT 提示中获得的收益较小。

CoT 提示的类型#

CoT 提示主要有两种类型：

  • 少样本 CoT。通过向模型提供少量示例来提示，每个示例都包含手动编写（或模型生成）的高质量推理链。

技巧与扩展#

  • 自一致性采样可以通过采样多个不同的答案然后取多数投票来提高推理准确性。（Wang et al. 2022a）

  • 集成学习的另一种方法是改变示例顺序或使用模型生成的推理过程来替代人工编写的推理过程，以在多次采样试验中引入随机性。然后通过多数投票聚合模型输出以获得最终答案。（Wang et al. 2022b）

  • 如果训练示例只关联正确答案（易于验证！）而没有推理过程，我们可以遵循STaR（自教推理器；Zelikman et al. 2022）方法：(1) 让LLM生成推理链，只保留那些导向正确答案的推理链；(2) 然后使用生成的推理链微调模型，重复此过程直至收敛。注意，较高的温度更可能生成带有正确答案的错误推理链。如果训练示例没有真实答案，可以考虑使用多数投票作为"正确"答案。

  • 包含更高推理复杂度示例的提示可以实现更好的性能，其中复杂度通过推理链中的推理步骤数量来衡量。当分离推理步骤时，换行符\n比step i、句号.或分号;效果更好。（Fu et al. 2023）

  • 基于复杂度的一致性是通过在仅前$k$个最复杂的推理链中进行多数投票，明确偏好所有生成中最复杂的推理链。（Fu et al. 2023）

  • 后来，Shum et al. (2023)发现在他们的实验中，仅使用复杂示例的CoT提示可以提高复杂问题的准确性，但在简单问题上表现不佳；在GSM8k数据集上有所体现。

  • 研究发现，将 Q: 改为 Question: 会更有帮助。（Fu et al. 2023）

  • Ye & Durrett (2022) 发现，在提示中包含解释对涉及文本推理的 NLP 任务（即问答和自然语言推理）的助益较小到中等，且效果因模型而异。他们观察到，解释更有可能是非事实性的，而非不一致的（即解释是否蕴含预测）。非事实性的解释很可能导致错误的预测。

  • Self-Ask（Press et al. 2022）是一种通过反复提示模型来 提出后续问题，从而迭代构建思维过程的方法。后续问题可以通过搜索引擎的结果来回答。类似地，IRCoT（交错检索思维链；Trivedi et al. 2022）和 ReAct（推理 + 行动；Yao et al. 2023）将迭代式思维链提示与维基百科 API 查询相结合，以搜索相关实体和内容，然后将其添加回上下文中。

  • Tree of Thoughts（Yao et al. 2023）通过在每个步骤探索多种推理可能性来扩展思维链。它首先将问题分解为多个思维步骤，并为每个步骤生成多种思维，本质上创建了一个树状结构。搜索过程可以是广度优先搜索或深度优先搜索，而每个状态则通过分类器（通过提示）或多数投票进行评估。

自动提示设计#

Prompt 是一系列前缀标记，用于在给定输入的情况下提高获得期望输出的概率。因此，我们可以将它们视为可训练的参数，并通过梯度下降直接在嵌入空间中进行优化，例如 AutoPrompt (Shin et al., 2020)、Prefix-Tuning (Li & Liang (2021))、P-tuning (Liu et al. 2021) 和 Prompt-Tuning (Lester et al. 2021)。我在《可控神经文本生成》文章中的这一节对它们有很好的介绍。从 AutoPrompt 到 Prompt-Tuning 的趋势是设置逐渐简化。

APE（自动提示工程师；Zhou et al. 2022）是一种在模型生成的指令候选池中进行搜索，然后根据选定的评分函数过滤候选集，最终选择得分最高的最佳候选的方法。

  1. 让 LLM 基于少量输入-输出对形式的示例生成指令候选。例如 {{Given desired input-output pairs}}\n\nThe instruction is。

  2. 给定一个数据集 $\mathcal{D}_\text{train} = \{(x, y)\}$，我们希望找到一个指令 $\rho$ 使得 $\rho^* = \arg\max_\rho \mathbb{E}_{(x, y) \in \mathcal{D}_\text{train}} [f(\rho, x, y)]$，其中 $f(.)$ 是一个样本级评分函数，例如执行准确率 $\mathbb{1}[\text{LM}(.\vert \rho, x)=y]$ 或对数概率：$p_\text{LM}(y \mid \rho, x)$。

  3. 使用迭代蒙特卡洛搜索方法，通过类似 Generate a variation of the following instruction while keeping the semantic meaning.\n\nInput: ...\n\nOutput:... 的提示来提出语义相似的变体，从而改进最佳候选。

为了自动构建思维链提示，Shum et al. (2023) 提出了增强-修剪-选择的三步流程：

  1. 增强：使用少样本或零样本思维链提示，针对问题生成多条伪思维链；
  2. 剪枝：根据生成的答案是否与真实答案匹配，对伪思维链进行剪枝；
  3. 选择：采用一种方差缩减的策略梯度方法来学习所选示例的概率分布，同时将示例的概率分布视为策略，将验证集准确率视为奖励。

Zhang 等人 (2023) 则采用了 聚类 技术来采样问题，然后生成思维链。他们观察到，大型语言模型（LLMs）倾向于犯某些特定类型的错误。其中一类错误在嵌入空间中可能相似，从而被归为一组。通过只从高频错误聚类中选取一个或少数几个示例，我们可以避免某一错误类型出现过多错误示范，同时收集到多样化的示例集。

  1. 问题聚类：对问题进行嵌入，然后运行 $k$-means 聚类算法。
  2. 示范选择：从每个聚类中选择一组代表性问题；即每个聚类选择一个示范。每个聚类中的样本根据到聚类中心的距离进行排序，优先选择距离中心较近的样本。
  3. 推理生成：使用零样本思维链为选定的问题生成推理链，并构建少样本提示以进行推理。

增强语言模型#

Mialon 等人 (2023) 的一篇关于增强语言模型的综述，全面涵盖了多种具备推理能力和使用外部工具能力的语言模型类别。强烈推荐阅读。

检索#

在许多情况下，我们需要完成那些需要模型预训练时间点之后最新知识，或内部/私有知识库中的知识的任务。在这种情况下，如果我们不在提示中明确提供上下文，模型将无法知晓相关信息。许多用于 开放域问答 的方法都依赖于先在知识库中进行检索，然后将检索到的内容作为提示的一部分。这类流程的准确性同时取决于检索和生成两个步骤的质量。

Lazaridou 等人 (2022)研究了如何利用 Google 搜索进行文档检索，以增强大型语言模型（LLM）。给定一个问题 $q$，从 Google 返回的 20 个 URL 中提取出干净的文本，形成一组文档。由于这些文档很长，每个文档被分割成 6 句话为一个段落的集合 $\{p\}$。基于证据段落与查询之间的 TF-IDF 余弦相似度对段落进行排序。在提示中只使用最相关的段落来生成答案 $a$。

对于闭卷问答，每个演示样本的格式如下，用于构建少样本提示。研究发现，将问题与证据互换（拉大问题与答案之间的距离）在所有数据集上都会导致结果持续变差。

Evidence: ...
Question: ...
Answer: ...

答案概率的计算有三种方式：

  1. RAG 方式，$p(a_i \mid q) = \sum_{i=1}^n p_\text{tf-idf} (p_i \mid q) \cdot p_\text{LM}(a_i \mid q, p_i)$，其中 $p_\text{tf-idf} (p_i \mid q)$ 是 TF-IDF 段落与查询表示之间的归一化余弦相似度。
  2. 噪声信道推理，$p(a_i\mid q) = \frac{p_\text{LM}(q \mid a_i, p_i) \cdot p_\text{LM}(a_i \mid p_i)}{p_\text{LM}(q \mid p_i)}$
  3. 专家乘积（PoE），结合了上述所有概率以及 $p_\text{LM}(p_i \mid q)$。

根据他们在生成和分类任务上的实验，在三种答案重排序分数中 - PoE > 噪声信道 > RAG。在各个单独的概率中，$p_\text{LM}(a \mid q, p_i)$ 和 $p_\text{LM}(q \mid p_i, a)$ 被发现是最具信息量的。$p_\text{LM}(q \mid p_i, a)$ 衡量了在给定证据段落和答案的情况下，语言模型对问题的解释能力，并且可以可靠地用于重排序答案候选。

在针对不同日期问题的 SituatedQA 数据集上，一个有趣的发现是：尽管语言模型（预训练截止到 2020 年）可以通过 Google 搜索获取最新信息，但它在 2020 年后问题上的表现仍然比 2020 年前的问题差很多。这表明上下文信息和模型内部知识之间可能存在某些差异或冲突。

Generate some knowledge about the input. Examples:

然后利用模型生成的知识，进一步提示语言模型以获得答案。

编程语言#

PAL（程序辅助语言模型；Gao et al. 2022）和PoT（思维链程序提示；Chen et al. 2022）都要求大型语言模型生成编程语言语句来解决自然语言推理问题，从而将解决方案的步骤卸载到 Python 解释器等运行时环境中。这种设置将复杂的计算和推理解耦开来。它依赖于具备足够编程能力的语言模型。

外部 API#

TALM（工具增强语言模型；Parisi et al. 2022）是一种通过文本到文本 API 调用增强的语言模型。语言模型被引导根据任务输入文本生成 |tool-call 和 tool input text 来构建 API 调用请求。当出现 |result 时，指定的工具 API 会被调用，并将返回的结果追加到文本序列中。最终输出在 |output 标记之后生成。

TALM 采用自我对弈的方法，逐步构建工具使用示例数据集，并用它来微调语言模型。这种自我对弈指的是模型与工具 API 进行交互，根据新添加的工具 API 是否能提升模型输出来迭代扩展数据集。Toolformer 也采用了同样的思想，下文会做更详细的介绍。这个流程大致模仿了强化学习过程，其中语言模型作为策略网络，通过带二元奖励信号的策略梯度进行训练。

Toolformer (Schick et al. 2023) 是一个能通过简单 API 使用外部工具的语言模型，它以自监督方式构建，每个 API 只需要少量示例即可。Toolformer 的工具箱包括：

  • 计算器：帮助语言模型弥补数学计算能力的不足；
  • 问答系统：解决内容不忠实和幻觉问题；
  • 搜索引擎：提供预训练截止时间后的最新信息；
  • 翻译系统：提升在低资源语言上的表现；
  • 日历：让语言模型能够感知时间流逝。

Toolformer 的训练流程如下：

  1. 通过提示标注潜在的 API 调用。让预训练的语言模型通过少样本学习，使用 API 调用示例来标注数据集。格式示例如下：

- 每个 API 调用表示为一个元组 (API 名称, 对应输入)，即 $c=(a_c, i_c)$，其对应的结果记为 $r$。带结果和不带结果的 API 调用序列分别标记如下：

    <div>
    $$
    \begin{aligned}
    e(c) &= \langle\texttt{API}\rangle a_c(i_c) \langle\texttt{/API}\rangle \\
    e(c, r) &= \langle\texttt{API}\rangle a_c(i_c) \to r \langle\texttt{/API}\rangle
    \end{aligned}
    $$
    </div>

- 基于概率 $p_\text{LM}(\langle\texttt{API}\rangle \mid \text{prompt}(\mathbf{x}), \mathbf{x}_{1:i})$ 进行示例 API 调用，如果在位置 $i$ 的概率大于某个阈值，则选择前 $k$ 个候选位置进行 API 调用。

- 然后我们从语言模型中采样潜在的 API 调用，给定序列 $[\text{prompt}(\mathbf{x}), x_1, \dots, x_{i-1}, \langle\texttt{API}\rangle]$ 作为前缀，$\langle\texttt{/API}\rangle$ 作为后缀。

  1. 根据 API 调用是否有助于模型预测未来 token 来过滤标注。 使用自监督损失来决定哪些 API 调用真正有帮助。

    • 执行每个 API 调用 $c_i$ 以获得对应的结果 $r_i$。

    • 当模型以 prompt 作为前缀时，计算语言模型在 tokens $x_i, \dots, x_n$ 上的加权交叉熵损失。计算两个版本，一个包含 API 结果，另一个使用空序列 $\varepsilon$。

      $$ \begin{aligned} L^+_i &= L_i(e(c_i, r_i)) \\ L^-_i &= \min(L_i(\varepsilon), L_i(e(c_i, \varepsilon))) \\ \end{aligned} $$

      只有当 $L^-_i - L^+_i$ 大于某个阈值时，才保留该 API 调用，这意味着添加这个 API 调用及其结果有助于模型预测未来的 tokens。

  2. 在此标注数据集上微调语言模型。 新的训练序列构造为 $\mathbf{x}^* = x_{1:i-1}, e(c_i, r_i), x_{i:n}$。训练数据是原始数据集（例如论文中提到的 CCNet 的子集）及其增强版本的组合。

在推理时，解码过程会持续进行，直到模型生成“$\to$ ” token，这表示它期望接下来接收来自 API 调用的响应。

目前 Toolformer 不支持链式工具使用（即使用一个工具的输出作为另一个工具的输入）或交互式工具使用（即根据人工选择采纳 API 响应）。这两者都是扩展模型的有趣未来方向。
