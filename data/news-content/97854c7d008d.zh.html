TurboFieldfare

Gemma 4 26B-A4B 推理仅需约 2GB 内存
专为 Apple Silicon Mac 打造的自定义 Swift + Metal 运行时，即使是 8GB 内存的小 Mac 也能运行。

快速入门 · 本地服务器 · 性能基准 · 贡献结果 · 工作原理 · 实验记录 · 参考资料

内存变得昂贵了。所以我给一个拥有 260 亿参数的模型分配了约 2 GB 的内存预算。

TurboFieldfare 运行指令微调的 Gemma 4 26B-A4B 时，并不会将整个 14.3 GB 的模型都加载到内存中。它将共享的 1.35 GB 核心和 FP16 KV 缓存保留在内存中，然后仅将每个 token 所需的专家模块从 SSD 流式传输。这就是该模型能够在 8 GB RAM 的 Mac 上运行的原因。

其运行时、流式安装器、CLI 和原生 Mac 应用均使用 Swift 和 Metal 编写。TurboFieldfare 是针对特定模型的实现，而不是 MLX 或 llama.cpp 的封装。精心整理的 实验记录 总结了在内核、缓存、I/O、prefill 和 decode 方面共 103 项测量结果。

试用一下

git clone https://github.com/drumih/turbo-fieldfare.git
cd turbo-fieldfare
swift build -c release
.build/release/TurboFieldfareMac

首次运行时，Swift Package Manager 会下载并构建分词器所需的 Swift 包。完整的发布构建包含前台 Mac 应用及其配套的 decode-service 可执行文件。

当应用打开时，选择下载，让 TurboFieldfare 获取并重新打包固定的模型（约 15 GB）。完成后，选择加载模型，输入提示词，然后点击生成。

使用 TurboFieldfare

TurboFieldfare 提供原生 Mac 应用、命令行接口和实验性的回环 OpenAI 兼容服务器。它们使用相同的 .gturbo 模型目录，但同一时间只能运行一个拥有模型的产品。

Swift 包包含六个产品：

产品 用途
TurboFieldfare 包含运行时和 Metal 内核的 Swift 库
TurboFieldfareMac 用于安装和生成的原生 Mac 应用
TurboFieldfareDecodeService Mac 应用使用的单次本地模型和 Metal 所有者
TurboFieldfareCLI 命令行指令聊天和原始补全
TurboFieldfareServer 回环 OpenAI 兼容的聊天补全服务器
TurboFieldfareRepack 流式模型安装程序和安装验证器

系统要求

  • 配备 Apple Silicon 芯片的 Mac；已验证的目标机型是 8GB 内存的 M2 MacBook Air
  • macOS 26 和 Metal 4
  • Xcode 26 和 Swift 6.2 或更高版本
  • 有约 14.3 GB 模型安装所需的足够可用存储空间
  • 首次安装模型时需要网络连接

该软件包仅支持 arm64 架构。不支持旧版本的 macOS 和 Metal。

模型提示词

Mac 应用会将您输入的内容视为指令，并自动处理 Gemma 的聊天格式。只需描述任务并提供模型所需的任何上下文信息即可。

生成参数默认为温度 0.2、Top-K 64 和 Top-P 0.95。将温度设置为 0 可获得确定性贪心输出。模型仍可能重复自身或给出错误答案，因此请检查重要结果。

TurboFieldfare 仅支持文本。应用和 CLI 支持用户和模型消息，以及可选的系统指导；它们不暴露或执行工具。回环服务器接受函数工具声明，并返回模型生成的工具调用，供客户端授权和执行。不支持图像、音频和视频。

Mac 应用

克隆仓库，然后从其根目录运行应用：

swift build -c release
.build/release/TurboFieldfareMac

构建完整包，使应用及其配套的解码服务都可用。从此代码库启动时，应用会将模型存储在 scratch/gemma4.gturbo 中。

安装模型

首次启动时，应用会检查可用存储空间并显示下载和安装大小。选择 下载 开始。

安装程序不会完整展开源检查点。它会从固定的 Hugging Face 版本中流式传输所需的字节范围，并在数据到达时直接重新打包成 .gturbo 格式。这避免了磁盘上出现第二个完整检查点，并将内存占用控制在有限范围内。

首次安装通过有界的 Hugging Face 范围请求传输约 15 GB 数据。网络速度和 Hugging Face 响应时间各不相同，因此可能需要一些时间。完成的 .gturbo 安装占用约 14.3 GB，仅在清单和文件哈希验证通过后才被接受。安装不会将模型加载到内存中。

加载和生成

安装完成后：

  1. 选择 加载模型。
  2. 在编辑器中输入提示词。
  3. 选择 生成，或按 Command+Return。
  4. 使用停止按钮或 Escape 键提前结束生成。

状态栏显示生成进度、解码速度和内存使用情况。使用右侧面板配置采样、上下文长度、专家缓存槽位和运行时选项。详细信息及默认值请参阅 运行时控制。

命令行界面

CLI 使用现有的 .gturbo 安装。如果你通过 Mac 应用安装了模型，它已经位于 scratch/gemma4.gturbo。否则，请从命令行安装：

swift run -c release TurboFieldfareRepack \
  --output scratch/gemma4.gturbo \
  --overwrite

继续被取消或中断的下载：

swift run -c release TurboFieldfareRepack \
  --output scratch/gemma4.gturbo \
  --overwrite \
  --resume

删除已保存的下载状态：

swift run -c release TurboFieldfareRepack \
  --discard-partial \
  --output scratch/gemma4.gturbo

运行时只接受包含最终 manifest.json 的完整 .gturbo 目录。

在不加载模型的情况下验证现有安装：

swift run -c release TurboFieldfareRepack \
  --verify-install \
  --input-gturbo scratch/gemma4.gturbo

指令对话

将聊天消息放入 JSON 数组，并通过 --messages-file 参数传递：

[
  {"role": "user", "content": "Explain why chunked prefill reduces time to first token while keeping memory bounded."}
]
swift run -c release TurboFieldfareCLI \
  --model scratch/gemma4.gturbo \
  --messages-file messages.json

这会以与 Mac 应用相同的方式格式化消息。CLI 的响应限制通过 --max-new 设置，默认为 1,024 个 token。Mac 应用可以持续生成，直到选定的上下文窗口被填满。

原始补全

--prompt 可用于原始补全和可复现的对比。它会将文本直接传递给模型，不进行对话格式化。请使用 --messages-file 进行指令-响应式对话。

swift run -c release TurboFieldfareCLI \
  --model scratch/gemma4.gturbo \
  --prompt "The capital of France is" \
  --max-new 64 \
  --temperature 0

此示例特意请求了一个简短的贪婪补全。

常见的生成选项包括 --max-context、--temperature、--top-k、--top-p、--repetition-penalty、--seed 和可重复的 --stop 字符串。公共 CLI 使用生产运行时默认值。运行以下命令获取完整选项列表：

swift run -c release TurboFieldfareCLI --help

生成的文本输出到标准输出，计时统计输出到标准错误； 在脚本中添加 --quiet 可以隐藏底部的统计信息。

本地 OpenAI 兼容服务器

构建服务器并指向已安装的模型：

swift build -c release --product TurboFieldfareServer
.build/release/TurboFieldfareServer \
  --model scratch/gemma4.gturbo

服务器监听 http://127.0.0.1:8080/v1，支持聊天补全、流式输出、函数工具和单前缀提示重用。客户端必须授权并执行每个工具调用。请将服务器保持在本地回环地址；它没有远程认证或 TLS。

有关测试请求、Python 和 OpenCode 设置、提示重用、工具处理以及支持的 API 子集，请参阅 本地服务器。

推理引擎工作原理

在每个 transformer 层，Metal 计算注意力机制和路由器，使用常驻权重。CPU 利用路由器的前 8 个专家 ID 来规划该层的 16 槽 LFU 缓存，然后通过有界并行 pread 调用将缺失项填入 Metal 可见缓冲区。在读取运行期间，Metal 计算常驻共享专家分支，然后合并共享和路由输出。

提示预填充使用最多 128 个 token 的块，这样一次获取的专家可以服务多行数据。生成过程则逐个 token 重复路由层循环。安装程序采用相同的内存限制规则：它直接将远程范围重新打包到 .gturbo 文件中，而不暂存完整的分片或张量。

有关模型架构的直观介绍，请参阅 Maarten Grootendorst 的 Gemma 4 视觉指南。

系统设计 解释了 .gturbo 布局、内存所有权、预填充、路由移交、cb1/io/cb2 阶段、Metal 内核以及正确性不变量。

状态与范围

TurboFieldfare 目前包括：

  • 远程流式重组为 .gturbo 模型格式
  • 经过微调的 Gemma 4 26B-A4B 指令模型，已验证纯文本聊天格式
  • 4 位 MLX 仿射嵌入、注意力、共享专家和路由专家权重，搭配 8 位路由器
  • 用于量化 GEMV、注意力、MoE、归一化、RoPE、采样和生产级融合的自定义 Metal 内核
  • 基于 SSD 的路由专家流式处理，配备有界专家缓存
  • 分块式单提示预填充和逐词生成
  • FP16 KV 存储，包含 25 个滑动窗口层的有界环形存储和 5 个全注意力层的线性存储
  • 具有独立归一化 K 和 V 路径的精确分块 K/V 解码注意力机制
  • 一个 Swift 库、流式安装器、命令行界面、回环式 OpenAI 兼容服务器，以及带一次性本地解码服务的原生 SwiftUI/AppKit Mac 应用

当前范围是在配备至少 8GB 内存的 Apple Silicon Mac 上，基于固定的 Gemma 4 26B-A4B 指令检查点进行纯文本推理。
