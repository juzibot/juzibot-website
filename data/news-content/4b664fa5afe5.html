内容简介

原帖通报 LM Studio 在 0.4.14 Build 2（Beta）中新增了对 MTP（多阶段/投机解码，speculative decoding）的支持。使用该功能需要将 llama.cpp 引擎升级到 2.15.0，并在加载模型前勾选“Manually choose model load parameters”（手动选择模型加载参数）然后启用 MTP，因为 MTP 默认未开启。帖子配了截图展示版本要求和设置位置说明。

社区观点

有人发了非正式基准：在一台 Windows 11（AMD 3900x + 2060 Super）上对 Qwen3.6-35B 测试，LM Studio 0.4.14 beta2 + CUDA12 约 8.2 tps，而优化过的 llama-server（CUDA 13.2）达到 18.5 tps，说明专门优化的服务器明显更快；有用户在 3090 上用 Qwen3.6-27B 测得大约 2× 的速度提升，但结果受量化、草稿模型配对和硬件影响较大；不少人认为投机解码对感知速度提升明显，尤其是大模型生成时令卡顿变少；有人提问哪些 Qwen 版本支持 MTP 或是否能与 Gemma 4 配合使用，表明模型兼容性仍是关切点；有用户找不到界面选项，提示需要在加载前开启“手动选择模型加载参数”并勾选 MTP，界面可发现性成为问题；也有声音坚称直接用 llama.cpp/llama-server 的优化构建比 LM Studio 内置体验更好，指出 LM Studio 在优化和可调参数上落后于社区构建；总体共识是 MTP 是有价值的性能功能，但收益高度依赖模型、量化、草稿模型以及本地硬件/驱动配置。

内容导读

这条信息的关键点是：LM Studio 正式在 0.4.14 Build 2（Beta）引入了对 MTP（投机解码/Speculative Decoding）的支持，但它不会自动启用，需要同时满足两个先决条件并手动开启——升级你的 llama.cpp 引擎到 2.15.0，并在加载模型之前选择“Manually choose model load parameters”然后勾选 MTP。理解它的价值：MTP 通过使用一个更轻量的“草稿模型”（draft model）来预测后续候选，从而减少主模型的解码工作量，因而能显著提高每秒生成令牌数（tps），改善交互时的延迟感。但要注意三点：一是性能提升并非对所有模型/量化配置都一致，某些量化格式或草稿/主模型配对会影响效果；二是会有额外内存/显存开销（载入草稿模型），需要确认你的 GPU/系统能负担；三是与经过高度优化的 llama-server 或自编译的 llama.cpp 二进制体相比，LM Studio 的默认表现可能不及专门优化的部署，因此建议在自己常用的模型和硬件上做对比基准测试来决定是否开启。此外，若遇到找不到选项或兼容性问题，先确认 LM Studio 版本是 0.4.14 Build 2（Beta）且 llama.cpp 为 2.15.0，再在模型加载前启用手动参数并勾选 MTP，最后根据实际 tps、显存占用与推理稳定性来判断是否长期使用。
