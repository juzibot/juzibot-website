检查必需参数 #

这操作是不是很熟悉？现在对我来说已经近乎肌肉记忆了。你有一个脚本，它需要几个参数，其中一些是必需的；好吧，就像以前无数次那样，来个 if 语句：

if [ -z "$1" ]; then
   echo "缺少参数，中止执行。" 1>&2
   exit 1
fi

echo "你好 $1!"

不过...如果我告诉你，上面这四行代码可以被替换成...仅仅一行呢？

: "${1:?missing argument, aborting.}"
echo "Hello $1!"

$ bash example.sh
example.sh: line 1: 1: missing argument, aborting.

$ bash example.sh refp
Hello refp!

再看看如果我们用一个有意义的变量名会发生什么——行为和之前一样，但更容易发现；诊断信息里包含了我们变量的名字！

: "${GREET_NAME:?missing argument, aborting.}"
echo "Hello $GREET_NAME!"

$ bash greet.sh
greet.sh: line 1: GREET_NAME: missing argument, aborting.

参数扩展与 :? 的故事 #

上一段代码里有两个知识点，你猜对了，其中一部分用到了 parameter expansion（参数扩展）：

  • 语法 ${name:?diagnostic} 会检查 $name 是否未设置或为空 — 如果是，则诊断信息会被打印到 stderr（标准错误），然后 shell 以非零状态退出；否则；

  • 如果变量已设置，它就等同于 $name。

那个.. 另一个冒号 #

这是一个冒号，但另一个呢？那个独自待在行首的？

  • : 是 null-command — 一个内置命令，它会计算参数的值，然后直接丢弃结果。

  • : 历史悠久，它最早可以追溯到 1971 年的 Thompson shell，当时它既可以用作 标签，也是 Unix 最早的注释标记。

  • : 就像黑暗中一双爱意满满的眼睛凝视着你。

更多冒号登场 #

也许我们已经证明了 : 远不止表面看起来那么简单，但为了展示 null-command 的真正魔力——这里有几个让我大开眼界的用法。

: "${DATA_DIR:=/var/data}"       
: "${RETRIES:=3}"                

: > error.log                    
: > error.log > access.log       

( : < dataset.json ) && echo YES 
( : >> result.json ) && echo YES 

trap : INT                       
sleep 60                         

set -u                           
: "$DEPLOY_ENV" "$HOST"          

if some-command; then
    :                            
else
    echo "command failed"
fi

所以，如果你和我一样，更喜欢少打几个字（gotta go fast）——那么 null-command 和 parameter expansion 这对组合值得你在咖啡变凉前好好研究一下。

而且.. 这难道不——很神奇吗？

set  : : : : : : : : : : : : : : : : : : : : :

while : colons are more than "${1:?magic}"; do
    echo "$*" && shift
done

常见问题 #

在网上看了几条评论后，我发现我漏掉了一些值得解释的内容。我会随着问题的出现不断更新这部分内容。

  • 为什么我需要空命令？没有冒号参数展开不会发生吗？ #

    参数展开无论如何都会发生，但如果没有空命令或类似的用法，shell 会将结果字符串当作要运行的命令来处理。

    % ${HELLO:=123}
zsh: command not found: 123

    如果我们在参数展开前加上空命令，结果会被丢弃，但表达式仍然会被求值（将 HELLO 设置为 123）。

    % : ${HELLO:=123}
% echo $HELLO
123

  • 为什么我可以用 VAR=${VAR:-default-value} 却还要用空命令？ #

    这本质上归结于个人偏好，但使用我们心爱的冒号可以将潜在拼写错误数量减少到一个（而不是两个）：

    : "${DATA_DIR:=/var/data}"           
DATA_DIR="${DATA_DRI:-/var/data}"

  • 当这些做法会影响可读性时，我为什么还要用？ #

    对于本文中提出的——非常刻意——的例子，存在一些常见的误解，有人质疑它们的实用性，或者根本不确定是否应该使用这些技巧。

    我们来看下面的例子。

    if some-command; then
    :                            
else
    echo "command failed"
fi

    当然，你可以用 if ! some-command 来消除分支，但这并不是这个代码片段的重点——重点在于展示空命令可以在需要命令但又不希望执行任何操作的地方使用。

    它的本意不是要被理解为 "哦，如果我有一个 if 语句，我就应该用空命令"，而是要被理解为 "哦，如果我处于一个需要命令的上下文中，我可以使用空命令来让它变成一个空操作（no-op）"。
