Ruff v0.16.0 现已发布！你可以从 PyPI 安装，或者使用你喜欢的包管理器：

uv tool install ruff@latest

温馨提示：Ruff 是一个用 Rust 编写的超快 Python 代码检查与格式化工具。 Ruff 可以替代 Black、Flake8（及其数十个插件）、isort、pydocstyle、pyupgrade 等工具，同时执行速度比任何单个工具都要快上几十甚至几百倍。

升级到 v0.16 #

Ruff v0.16 只有一些小的破坏性变更，大多数用户无需对代码或配置进行重大修改即可升级。主要例外情况如下所述。

更好的默认规则集 #

Ruff 默认启用的规则数量从之前的 59 条增加到 413 条。

自 Ruff 的默认规则集上次在 v0.1.0 中修改以来，Ruff 的规则总数已从 708 条增加到 968 条。其中许多规则能够捕获严重问题，包括 语法错误 和 即时运行时错误，但这些规则之前并未默认启用。有了新的规则集，Ruff 会在没有任何配置的情况下向你提醒这些问题以及许多其他问题。即使你已经在使用 select 或 extend-select，我们也希望这能让你注意到那些你之前未曾发现的有用规则。

完整的启用规则列表太长，无法在此处全部列出，但你可以在我们文档中新增的 默认规则 页面上找到它们。其中一些亮点包括来自流行的 flake8-bugbear (B) 和 pyupgrade (UP) 检查工具的规则，以及我们自己 RUF 类别的规则。

如果你想恢复到旧的默认规则集，你可以使用以下配置轻松 select 旧规则：

[lint]
select = ["E4", "E7", "E9", "F"]

我们认为这项工作与我们长期以来致力于的规则重新分类目标密切相关，因此期待该领域的后续发展。

v0.16 的新功能 #

Ruff v0.16 还包含几个新稳定的功能，下面将重点介绍。

Markdown 代码块格式化 #

Ruff 现在可以格式化嵌入在 Markdown 文件中的 Python 代码块。

在这些文件中，Ruff v0.16 将格式化带有 python、py、python3、py3、pyi 或 pycon 信息字符串的围栏代码块。pyi 块的格式与存根文件类似，pycon 块的格式与 REPL 会话类似，其他则使用标准的 Python 文件格式。例如：

# README

这是一个示例：

```py
import ruff

ruff_binary = (
    ruff.find_ruff_bin()
)
```

运行 ruff format 时，上述代码将被重新格式化：

这也可用于格式化 Quarto 笔记本，因为当语言被花括号包围时（例如 ```{python}），Ruff 仍然能够识别。请注意，如果您的 Quarto 文件使用 .qmd 扩展名，您可能需要配置您的 extension 映射。

如果您需要禁用格式化，有几种选择。如果您希望禁用注释出现在代码块中，可以在代码块内使用普通的 fmt: off 和 fmt: on 注释，或者使用类似的 HTML 注释来禁用整个文档区域的格式化：

# README

<!-- fmt: off -->

```py
x =      "this will be suppressed"
```

<!-- fmt: on -->

要完全禁用 Markdown 格式化，您可以使用普通的 extend-exclude 设置，通过类似 *.md 的 glob 模式排除所有 Markdown 文件。

更多详情请参阅完整文档。

ruff: ignore 注释提供新的抑制功能 #

Ruff 现在拥有自己的抑制注释格式，可以单独使用一行。

在 v0.15 版本中，Ruff linter 通过成对的 ruff: disable 和 ruff: enable 注释引入了范围抑制机制，这与上面描述的 fmt: off 和 fmt: on 对类似：

# ruff: disable[N803]
def foo(
    legacyArg1,
    legacyArg2,
    legacyArg3,
    legacyArg4,
): ...
# ruff: enable[N803]

Ruff v0.16 在此基础上增加了两种额外的 ruff 抑制注释。ruff: ignore 可以用于抑制同一行的诊断（类似 noqa），或抑制后续逻辑行的诊断：

import math  # ruff: ignore[F401]

# ruff: ignore[N803]
def foo(
    legacyArg1,
    legacyArg2,
    legacyArg3,
    legacyArg4,
): ...

在这种情况下，逻辑行跨越整个函数头（从 def 到冒号），因此 ruff: ignore 会抑制与上面 disable/enable 对相同的所有 N803 诊断。

ruff: file-ignore 注释可用于抑制整个文件的诊断，就像 ruff: noqa 注释一样：

# ruff: file-ignore[F401] 允许此文件中存在未使用的导入

import foo
import bar
import baz

如本例所示，每种注释类型都可以附带一个“原因”说明添加它们的原因，这里是 允许此文件中存在未使用的导入。

ruff: ignore 注释可以通过新的 --add-ignore CLI 标志自动添加，并且在 preview 版本中，所有这些 ruff 抑制注释都支持使用规则名称而非代码：

❯ echo 'import math' > try.py
❯ uvx ruff@latest check --preview --add-ignore try.py
已添加 1 个忽略注释。
❯ cat try.py
import math  # ruff: ignore[unused-import]

你可以在文档中找到所有这些注释的完整规范。

修复现在会在 check 和 format --check 输出中显示 #

Ruff 现在在显示诊断信息时会展示 linter 和 formatter 修复的 diff。

无论是 check 还是 format 子命令，早已支持 --diff 标志来显示通过 check --fix 或 format 应用修复所引入的更改，但这部分内容与常规输出是分开的，并且会附带抑制解释性的诊断信息。在 v0.16 版本中，现在可用的修复会作为默认 full 输出格式的一部分展示，显示在 help 子诊断信息下方：

format --check 也是如此。给定如下输入：

# example.py

if True:
    pass
elif     False:
    pass

format --check 现在也支持 linter 所支持的全部输出格式。你可以利用这一点获取机器可读的 JSON 输出，或生成 GitHub 和 GitLab 在 CI 中渲染注释所期望的格式，这里仅举几例。有关支持格式的完整列表，请参阅 CLI 帮助或 文档。

关于输出格式还有最后一点说明：在 v0.16 版本中，JSON 输出发生了一个小的破坏性变更。filename、location、end_location、fix.edits[].location 和 fix.edits[].end_location 字段现在可能为 null，而不再是默认的空字符串以及第 1 行第 1 列。这项改动应该只会影响极少数现有的 Ruff 诊断信息，但它能更好地反映内部的诊断信息表示方式，并且在未来规则中可能会变得更加普遍。

以下规则已稳定，不再处于 预览状态：

  • airflow3-incompatible-function-signature (AIR303)
  • missing-copyright-notice (CPY001)
  • unnecessary-from-float (FURB164)
  • sorted-min-max (FURB192)
  • implicit-string-concatenation-in-collection-literal (ISC004)
  • log-exception-outside-except-handler (LOG004)
  • invalid-bool-return-type (PLE0304)
  • too-many-positional-arguments (PLR0917)
  • stop-iteration-return (PLR1708)

  • access-annotations-from-class-dict (RUF063)

其他行为稳定化 #

本次发布还稳定了一些额外的行为，这些行为之前仅在 预览模式中可用：

  • blind-except (BLE001) 现在会在异常通过 logging 方法（critical、error 和 exception 除外）记录时自动抑制。
  • future-required-type-annotation (FA102) 现在会检查额外的 PEP 585 兼容 API，例如来自 collections.abc 的 API。
  • f-string-in-get-text-func-call (INT001)、 format-in-get-text-func-call (INT002) 和 printf-in-get-text-func-call (INT003) 现在会检查使用 gettext 模块的更多常见方式，例如将其赋值给 builtins._。
  • suspicious-url-open-usage (S310) 现在会解析本地字符串字面量绑定，以减少误报。
  • snmp-insecure-version (S508) 和 snmp-weak-cryptography (S509) 现在支持 新版 PySNMP 推荐的 API。
  • typing-text-str-alias (UP019) 现在除了 typing.Text 外，还能识别 typing_extensions.Text。
