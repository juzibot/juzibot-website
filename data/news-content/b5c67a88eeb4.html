Qwen3.8-Max is a new advanced 2.4 trillion parameter model, excelling in coding and various professional applications. It can autonomously code, complete real projects, plan with adaptive learning, and integrate multimodal intelligence. The model is set to release with open weights alongside Qwen3.8-27B. Pricing for token usage is specified. The release encourages users to start building with the model, providing links to their blog and API for further exploration. In benchmark tests, Qwen3.8-Max performs exceptionally well compared to other models.

内容简介

推文宣布发布 Qwen3.8-Max（参数规模 2.4T）及开放权重的计划，Qwen3.8-27B 也将开源权重。官方强调该模型在代码生成与协同工作能力上达到新标杆：自主编码（宣称能在 10+ 天内从空仓库自我演化到可生产项目，并在 GitHub 给出完整项目轨迹）、跨专业的生产级交付、长时间跨度的系统级自主规划与闭环自适应学习（示例包括芯片设计优化 500+ 次迭代与电商策略 365 天）、以及把视觉作为持续反馈回路的原生多模态智能。还公布了基于 API 的定价（输入 $2/百万 tokens、输出 $6/百万 tokens、隐式缓存 $0.25/百万 tokens）并附上博客、Qwen Studio 和 API 链接。

社区观点

1) 很多人为“开权重”感到兴奋：可用于研究、离线部署和二次开发，尤其是 27B 版本更易本地化；2) 也有大量怀疑声：对“10+ 天自演化”“从空文件夹到生产”的可复现性和评估细节表示质疑，要求公开完整评测与训练管线；3) 成本与部署问题被频繁提及：2.4T 模型的推理成本、显存与延迟挑战会很高，实际使用时多数团队会选择更小的可用权重；4) 定价引起争议：按百万 tokens 收费的模型端定价感到透明但偏高，用户关心长期使用成本与缓存策略的实际节省；5) 与其他大型模型比较的讨论很多，人们把 Qwen3.8-Max 与 GPT/Claude/LLaMA 系列对比，关注在多模态、长上下文与闭环自学习方面的差异；6) 隐私、合规与商用授权被反复提及：即便权重开源，企业仍需评估许可证、数据安全与部署后的责任；7) 一部分用户期待看到更多真实任务基准（尤其是长期规划、持续视觉反馈与代码质量的量化指标）来判断“生产级交付”的真实性。

内容导读

这条推文的核心是在宣布 Qwen3.8-Max（2.4T 参数）及 Qwen3.8-27B 的开权重计划，并且以若干实操案例（自主编码、自适应闭环学习、持续视觉反馈）来突出模型在编码、多模态与长时序规划上的能力。阅读时建议抓住三点：1）权重与可用性——开权重意味着研究者和工程团队可以下载、复现与定制，但 2.4T 的全量模型在硬件与推理成本上要求极高，实际生产中更可能采用 27B 或更小变体；2）能力主张需验证——官方给出了显著的应用示例，但要通过复现仓库、对比基准测试和任务级评价（如代码正确率、长期规划稳定性、视觉闭环的纠错率）来判断这些主张是否成立；3）成本与工程考量——除了 API 列出的按 token 定价外，务必评估端到端成本（推理硬件、延迟、缓存命中率与微调/部署开销）、合规/授权条款，以及在多模态流水线中如何使用视觉反馈做闭环控制。实践建议：先用开源的 27B 快速做本地/云端原型验证（代码质量、上下文记忆与多模态交互），用官方 GitHub 提供的工程轨迹复现实验，再按实际工作负载估算 API 或自托管总成本，重点考察 hallucination、长期稳定性与视觉反馈的效果。
