这本书是讲什么的？

这是一本关于如何更好地设计、验证和推理软件的书。它还讲述了学习一点逻辑——即布尔代数——是如何解锁我们领域中各种酷炫技巧的。

这本书主要是理论性的，还是也有实际应用？

书中的所有内容都旨在实用。前几章的主题包括“简化条件判断”和“确保API变更不会破坏客户端”。后几章则涉及一些更专业的主题，例如“在假设的软件设计中发现竞态条件”和“最小化分布式任务的挂钟时间”。不是所有内容对每个人都有用，但我希望每个人都能找到有用的东西！

我需要懂数学吗？

完全不需要！除了程序员在日常工作中会用到的布尔与、或、非运算，你不需要懂其他数学。书中会涵盖你所需的其他数学知识。

话虽如此，你确实需要懂一些编程！这本书面向的是中级到高级程序员，我假设读者了解循环、版本控制、测试等通用主题。有些章节需要更具体的知识，比如SQL或API设计。不过各章是独立的，所以如果某些内容不符合你的需求，可以直接跳过。

标题里那个奇怪的A和E是什么意思？

逻辑学家使用符号 ∀ 和 ∃ 来分别表示“对于所有”和“存在”。例如，我们可以将句子“每个人都有自己喜欢的颜色”写成 ∀p ∈ Person: ∃c ∈ Color: IsFavoriteColor(p, c)。

为了让学习主题（以及在书中搜索）更容易，我使用英文单词代替数学符号。因此，同样的表达式可以写成 all p in People: (some c in Color: IsFavoriteColor(p, c))。

为什么在 Python 中 all([]) == True？这让我一直很困惑。

Python 的 all 函数等价于以下写法：

all(l) = l[0] && l[1] && l[2] ...

这具有一个特定的性质：对于任意两个列表 xs 和 ys，我们有：

all(xs . ys) == all(xs) && all(ys)

但这个结论适用于任意两个列表，当然也包括空列表！如果我们选择 ys = [] 会发生什么？那么 xs . [] == xs，也就是说：

all(xs) && all([]) == all(xs . [])
all(xs) && all([]) == all(xs)

如果 all([]) = True，这个等式就变成了 all(xs) && True == all(xs)，也就是 all(xs) == all(xs)。如果 all([]) = False，那么等式就变成了 all(xs) && False == all(xs)xs 是什么，all(xs) 都等于 False。所以，为了保持这个特性，让 all(xs) = True 是更合理的。

我们说 True 是 && 的单位元：无论 p 是什么，p && True == p 都成立。顺便一提，同样的道理也解释了为什么空列表的和是 0，而空列表的 any 是 False。
