Inflect-Micro-v2

一个参数量不到 10M 的完整本地文本转波形语音合成模型。

评估

没有单一指标能完全衡量 TTS 质量。Inflect v2 分别报告 人类偏好、预测自然度、多 ASR 可懂度、完整 FP32 权重大小 和 运行时间，而不是将它们压缩成一个无法验证的分数。

社区偏好 ↑ UTMOS22 ↑ 双 ASR 语义词错率 ↓ 完整 FP32 权重大小 ↓ 4 线程 CPU 吞吐量 ↑
66.2% 4.395 3.99% 37.53 MB 6.28× 实时

标题行始终指代 Inflect-Micro-v2。详细的竞品结果和协议边界在下方保持可见。

对比集。结果包括 KittenTTS Nano、Piper Low 和 Supertonic 3，这些都是已确立的紧凑型或本地 TTS 基准模型，其可部署的权重体积比 Inflect 的两个版本都要大。权重大小在包级别进行比较，且没有任何单一指标被视为整体优越性的证明。

1. 人类盲听偏好

在最终匿名的社区研究中，Inflect-Micro-v2 的偏好率为 66.2%（21 胜 · 10 负 · 3 平）。系统信息被隐藏，左右顺序随机化，平局算作半胜。这是描述性的社区证据，而非正式的 MOS 分。

2. 预测自然度与体积对比

UTMOS22 测试对每个语音使用了 500 个相同的未见过的提示词。KittenTTS 和 Piper 是等权重的双语音平均值；其观察到的语音范围显示为须线。Supertonic 3-step 的数据点绘制在图表范围下方，而不是为了不压平其他系统。

Inflect-Micro-v2: 4.395 UTMOS22，95% 自助法置信区间为 4.381–4.408。UTMOS22 是一个学习型预测器，而非人类 MOS 分。

3. 未见文本的可懂度

头条分数是 Qwen3-ASR 和 Nemotron 3.5 语料库 WER 的等权重平均值，适用于每个系统。Whisper 被一致排除在头条分数之外，因为它在部分可理解的 Supertonic 8-step 片段中产生了大量插入式幻觉。它没有被删除：完整的三套 ASR 证据如下所示。

4. CPU 运行时间

两个 Inflect 版本在 CPU 上的合成速度都轻松超过实时。管理型基准测试使用的是 Hugging Face 的 CPU 升级版 实例（8 vCPU，32 GB RAM），并采用 四个框架线程，进行端到端的文本到波形计时，以及 100 个固定的 Modern400 提示。记录了三次完整运行；第一次缓存构建运行被排除，表格数据取自第二次和第三次运行的汇总。

版本 稳态 RTF ↓ 音频/墙钟时间比 ↑
Inflect-Micro-v2 0.1593 6.28×
Inflect-Nano-v2 0.0933 10.72×

这些是公共 PyTorch 运行时的包级别结果，并非声称 Inflect 是最快的紧凑型 TTS 系统。硬件、前端行为、框架、编译和线程策略都会影响小模型的测量结果。

开放方向：紧凑型系统速度对比

同样的管理型 CPU 和四线程策略用于一次较短的对比测试：使用相同的 50 个提示前缀，重复两次。KittenTTS 和 Piper 的数据在其测试的两个语音间进行了等工作量汇总。

由于 Inflect 使用了更长的 100 提示稳态运行，而对比行使用了较短的 50 提示确认测试，因此此表展示的是部署场景下的性能对比，而非完全匹配的速度排行榜。部分对比模型还使用了优化的 ONNX 运行时，而上文发布的 Inflect 基准测试使用的是标准 PyTorch 运行时。单独发布的 Inflect ONNX 版本并未替换到这些基准测试数据中。

5. 完整模型占用空间

共享相同权重的语音变体会被合并。Inflect 的总大小包含了集成的波形解码器。

打开冻结评估协议
  • Modern400 对每个系统使用 400 个相同的未见过的英文提示：200 个固定的现代/压力提示加上 200 个确定性的 FLEURS en_us 测试提示。
  • 精确文本排除检查了 87,362 个训练转录文本。
  • 所有 ASR 输入都被重新采样到 16 kHz，并使用相同的公开英文标准化器进行评分。
  • UTMOS22 使用 tarepan/SpeechMOS v1.2.0 在一个独立的 500 提示生成集上进行评估。
  • 标题区间使用 10,000 个 bootstrap 样本。
  • Modern400 语料库的 SHA-256 是 b7504ce2dce44a2da82770a6a5dfd2a034fe17e2113980f8a69663ade417a34c。
  • 提示、假设、压缩的行级报告和摘要都存放在 evaluation/final/ 目录下。
  • 运行时单独评估，因为框架、线程策略、编译和主机负载可能会在小模型对比中占据主导地位。

本地运行

安装 

python -m pip install --upgrade huggingface_hub
hf download owensong/Inflect-Micro-v2 --local-dir Inflect-Micro-v2
cd Inflect-Micro-v2
python -m pip install -r requirements.txt

这使用了 Hub 的版本感知下载器，并获取完整的代码库。Git 克隆也可以，但 hf download 是推荐的普通模型安装方式。

Python 

from inference import InflectTTS

tts = InflectTTS(".", device="cpu")
tts.save(
    "A small voice can still have something meaningful to say.",
    "sample.wav",
    speed=1.0,
    variation=0.667,
    seed=7,
)

通过 Hub 下载 

import sys
from huggingface_hub import snapshot_download

model_dir = snapshot_download("owensong/Inflect-Micro-v2")
sys.path.insert(0, model_dir)

from inference import InflectTTS

tts = InflectTTS(model_dir, device="cpu")
sample_rate, waveform = tts.synthesize("The complete model runs locally.")

结果是一个 24 kHz 单声道 float32 波形。长文本会在标点感知的边界处分割，逐块合成，并以可控的停顿连接。

ONNX Runtime

官方验证的 FP32 导出版本单独发布为 Inflect-Micro-v2-ONNX。 它支持动态长度、CPU/CUDA/DirectML 提供商选择、确定性种子，以及无需导入 PyTorch 的相同长文本包装器：

git clone https://huggingface.co/owensong/Inflect-Micro-v2-ONNX
cd Inflect-Micro-v2-ONNX
python -m pip install -r onnx/requirements.txt
python onnx/inference_onnx.py \
  --text "The complete model now runs through ONNX Runtime." \
  --output sample-onnx.wav \
  --provider cpu \
  --seed 7

神经模型被拆分为 duration.onnx 和 decode.onnx；它们共同包含完整的文本到波形学习路径。英语 eSpeak-ng 前端仍然是 CPU 端代码。有关图契约、来源、一致性测量、浏览器部署和重新导出说明，请参阅 ONNX 仓库。

控制、确定性与长文本
控制项 默认值 公开范围 含义
speed 1.0 0.5–2.0 值越低越慢；值越高越快。
variation 0.667 0.0–1.0 值越低越稳定；值越高则采样更多潜在变化。
seed 0 整数 在相同运行时堆栈上重复相同的随机样本。

长文本按标点感知进行分块，而不是无限长的自回归处理。块边界会添加短暂停顿和边缘淡入淡出。有关波形约定和并发说明，请参阅 docs/API.md。

数据、语音与适配状态

本次发布包含一个固定的合成英语语音。该包不重新分发真实说话人的录音语料库，不声称该语音代表任何真实人物，并且在推理时无需参考音频或外部模型。

本次发布以推理优先。新语音和新语言适配功能目前尚未验证或支持。新增语音会替换固定说话人，而不是增加可选说话人；语言适配还需要重新构建标准化、音素、符号、嵌入和训练数据。请参阅 docs/DATA_AND_VOICE.md 和 docs/FINETUNING.md。

局限性

  • 仅支持英文，且只有一种固定的男声。这不是零样本语音克隆。
  • 不熟悉的表达可能会变得平淡、缺乏表现力或不稳定。
  • 数字、缩写、同形异义词和不常见名称仍需前端处理，且受上下文影响。
  • 长文本采用标点感知的分块处理；过渡效果可能与原生长模型生成的版本不同。
  • 随机变化可能影响语调和发音。进行对比时请固定随机种子。
  • UTMOS22 和 ASR 分数不能替代受控的人类 MOS 或 MUSHRA 式评估。
  • 未经验证用于医疗、法律、紧急或对无障碍至关重要的通信场景。

负责任的使用

请勿使用内置的语音来冒充真人、欺骗听众或创建欺诈性内容。在可能产生误导的上下文中，请明确说明这是合成语音。用户需遵守相关法律法规和 Apache-2.0 许可证。
