以大型语言模型（LLM）作为核心控制器来构建智能体是个很酷的概念。一些概念验证演示，比如 AutoGPT、GPT-Engineer 和 BabyAGI

智能体系统概述#

在由 LLM 驱动的自主智能体系统中，LLM 充当智能体的大脑，并辅以几个关键组件：

  • 规划
    • 子目标与分解：智能体将大任务分解成更小、易于管理的子目标，从而能够高效地处理复杂任务。
    • 反思与优化：智能体可以对过去的行动进行自我批评和反思，从错误中学习并优化后续步骤，从而提高最终结果的质量。
  • 记忆
    • 短期记忆：我认为所有上下文学习（参见 Prompt Engineering）都是利用模型的短期记忆进行学习。
    • 长期记忆：这为智能体提供了在长时间内保留和召回（无限）信息的能力，通常通过利用外部向量存储和快速检索来实现。
  • 工具使用
    • 智能体学会调用外部 API 来获取模型权重中缺失的额外信息（这些信息在预训练后通常很难更改），包括当前信息、代码执行能力、对专有信息源的访问等等。

组件一：规划#

一个复杂的任务通常涉及很多步骤。智能体需要知道这些步骤是什么，并提前规划。

任务分解#

思维链（CoT；Wei 等人 2022）已成为一种标准的提示技术，用于提升模型在复杂任务上的表现。该方法指导模型“逐步思考”，从而利用更多的测试时计算能力，将艰巨的任务分解为更小、更简单的步骤。思维链将大任务转化为多个可管理的子任务，并为理解模型的思考过程提供了新的视角。

思维树（Yao 等人 2023）通过在每个步骤探索多种推理可能性，对思维链进行了扩展。它首先将问题分解为多个思考步骤，并在每一步生成多个思考内容，从而形成一个树状结构。搜索过程可以采用广度优先搜索（BFS）或深度优先搜索（DFS），并由分类器（通过提示实现）或多数投票来评估每个状态。

任务分解可以通过以下方式实现：(1) 使用简单的提示让 LLM 完成，例如 "完成 XYZ 的步骤。\n1." 或 "实现 XYZ 需要哪些子目标？"；(2) 使用特定任务的指令，例如为写小说提供 "撰写故事大纲。"；(3) 通过人工输入。

另一种截然不同的方法是LLM+P（Liu 等人 2023），它依赖外部经典规划器进行长期规划。该方法利用规划域定义语言（PDDL）作为中间接口来描述规划问题。在这个过程中，LLM (1) 将问题转化为“问题 PDDL”，然后 (2) 请求经典规划器基于现有的“领域 PDDL”生成一个 PDDL 计划，最后 (3) 将 PDDL 计划翻译回自然语言。本质上，规划步骤被外包给了外部工具，这假设了特定领域的 PDDL 和合适的规划器是可用的——这在某些机器人设置中很常见，但在许多其他领域则不然。

自我反思#

自我反思是一个至关重要的方面，它使自主代理能够通过优化过去的行动决策和纠正之前的错误来持续改进。在试错在所难免的现实世界任务中，它扮演着关键角色。

ReAct (Yao et al. 2023) 通过将动作空间扩展为任务特定的离散动作与语言空间的组合，将推理和行动整合到大型语言模型（LLM）中。前者使LLM能够与环境交互（例如使用维基百科搜索API），而后者则促使LLM用自然语言生成推理轨迹。

ReAct的提示模板包含了明确的步骤来引导LLM进行思考，大致格式如下：

Thought: ...
Action: ...
Observation: ...
... (重复多次)

在知识密集型任务和决策型任务的实验中，ReAct的表现优于仅包含行动的Act基线模型（即移除了Thought: …步骤的模型）。

Reflexion (Shinn & Labash 2023) 是一个为智能体配备动态记忆和自我反思能力的框架，旨在提升其推理能力。Reflexion采用标准的强化学习设置，其中奖励模型提供一个简单的二元奖励，而动作空间则遵循ReAct的设置，将任务特定的动作空间与语言相结合，以支持复杂的推理步骤。在每个动作 $a_t$ 之后，智能体会计算一个启发式值 $h_t$，并根据自我反思的结果，选择性地决定重置环境以开始新的尝试。

启发式函数用于判断轨迹是否效率低下或包含幻觉，并决定是否应停止。效率低下的规划指的是那些耗时过长却未能成功的轨迹。幻觉则被定义为遇到一连串相同的动作，而这些动作在环境中产生了相同的观察结果。

自我反思是通过向大语言模型展示双样本示例来实现的，每个示例都是一组（失败轨迹，用于指导未来计划变更的理想反思）。然后将反思内容添加到代理的工作记忆中，最多三条，作为查询大语言模型的上下文使用。

后见之明链（CoH; Liu et al. 2023）通过明确展示一系列过去的输出（每个都带有反馈注释）来鼓励模型改进自身输出。人类反馈数据是一个集合$D_h = \{(x, y_i , r_i , z_i)\}_{i=1}^n$，其中$x$是提示，每个$y_i$是模型的完成输出，$r_i$是对$y_i$的人类评分，$z_i$是对应的人类后见之明反馈。假设反馈元组按奖励排序，即$r_n \geq r_{n-1} \geq \dots \geq r_1$。该过程是监督微调，数据形式为序列$\tau_h = (x, z_i, y_i, z_j, y_j, \dots, z_n, y_n)$，其中$\leq i \leq j \leq n$。模型在给定序列前缀的条件下被微调以只预测$y_n$，这样模型就能基于反馈序列进行自我反思以产生更好的输出。在测试时，模型可以选择性地与人工标注者进行多轮指令交互。

为避免过拟合，CoH添加了一个正则化项来最大化预训练数据集的对数似然。为避免捷径和复制行为（因为反馈序列中有很多常见词汇），他们在训练过程中会随机屏蔽0%-5%的过去token。

他们实验中的训练数据集是WebGPT对比数据、基于人类反馈的摘要和人类偏好数据集的组合。

CoH 的核心思想是在上下文中展示一系列逐步改进的输出，并训练模型遵循这种趋势以产生更好的输出。算法蒸馏（AD; Laskin et al. 2023）将同样的思想应用于强化学习任务中的跨回合轨迹，其中算法被封装在一个长历史条件策略中。考虑到智能体与环境进行多次交互，并且在每个回合中都会有所进步，AD 将这些学习历史拼接起来输入给模型。因此，我们可以期望下一个预测的动作能比之前的尝试带来更好的表现。其目标是学习强化学习的过程，而不是训练一个特定任务本身的策略。

该论文假设，任何能生成一组学习历史的算法，都可以通过对动作进行行为克隆来蒸馏成一个神经网络。历史数据由一组源策略生成，每个策略都针对特定任务进行训练。在训练阶段，每次强化学习运行时，会随机采样一个任务，并使用多回合历史的一个子序列进行训练，这样学到的策略就与任务无关。

实际上，模型的上下文窗口长度是有限的，因此回合应该足够短，以便构建多回合历史。要学习一个接近最优的上下文强化学习算法，2-4 个回合的多回合上下文是必要的。上下文强化学习的出现需要足够长的上下文。

与三个基线方法（包括 ED（专家蒸馏，使用专家轨迹而非学习历史的行为克隆）、源策略（通过 UCB 生成轨迹用于蒸馏）和 RL^2（Duan et al. 2017；由于需要在线 RL 而用作上限））相比，AD 展示了上下文 RL 的能力，其性能接近 RL^2，尽管仅使用离线 RL，并且比其他基线方法学习速度快得多。当基于源策略的部分训练历史进行条件化时，AD 的改进速度也比 ED 基线快得多。

组件二：记忆#

（非常感谢 ChatGPT 帮我起草本节。在与 ChatGPT 的 对话 中，我学到了很多关于人脑和快速 MIPS 数据结构的知识。）

记忆的类型#

记忆可以被定义为用于获取、存储、保留和 later 检索信息的过程。人脑中有多种类型的记忆。

  1. 感觉记忆：这是记忆的最早阶段，能够在原始刺激结束后保留感官信息（视觉、听觉等）的印象。感觉记忆通常只持续几秒钟。子类别包括图像记忆（视觉）、回声记忆（听觉）和触觉记忆（触觉）。

  2. 短期记忆（STM）或工作记忆：它存储我们当前意识到的信息，这些信息是完成复杂认知任务（如学习和推理）所必需的。短期记忆的容量约为7个项目（Miller 1956），持续时间约为20-30秒。

  3. 长期记忆（LTM）：长期记忆可以存储信息非常长的时间，从几天到几十年不等，并且具有基本上无限的存储容量。长期记忆有两种亚型：

    • 外显/陈述性记忆：这是对事实和事件的记忆，指那些可以被有意识回忆的记忆，包括情景记忆（事件和经历）和语义记忆（事实和概念）。
    • 内隐/程序性记忆：这种类型的记忆是无意识的，涉及自动执行的技能和常规，比如骑自行车或在键盘上打字。

我们可以大致考虑以下映射关系：

  • 将感觉记忆视为原始输入（包括文本、图像或其他模态）的学习嵌入表示；
  • 将短期记忆视为上下文学习。它是短暂且有限的，因为它受到 Transformer 有限上下文窗口长度的限制。
  • 将长期记忆视为代理在查询时可以关注的外部向量存储，可通过快速检索访问。

最大内积搜索 (MIPS)#

外部记忆可以缓解有限注意力范围的限制。一种标准做法是将信息的嵌入表示保存到支持快速最大内积搜索（MIPS）的向量存储数据库中。为了优化检索速度，常见的选择是使用近似最近邻（ANN）算法，返回近似的前k个最近邻，以牺牲少量准确性来换取巨大的速度提升。

用于快速 MIPS 的一些常见 ANN 算法选择：

  • LSH (局部敏感哈希)：它引入了一种哈希函数，使得相似的输入项有很高的概率被映射到同一个桶中，而桶的数量远小于输入的数量。
  • ANNOY (近似最近邻搜索)：其核心数据结构是随机投影树，这是一组二叉树，其中每个非叶节点代表一个将输入空间分成两半的超平面，每个叶节点存储一个数据点。树是独立随机构建的，因此在某种程度上模拟了哈希函数。ANNOY的搜索会在所有树中进行，迭代查询最接近查询结果的一半，然后聚合结果。这个想法与KD树非常相似，但可扩展性要好得多。
  • HNSW (分层可导航小世界)：它受到小世界网络的启发，在小世界网络中，大多数节点可以在很少的步骤内到达任何其他节点；例如社交网络中的“六度分隔”特性。HNSW构建了这些小世界图的分层结构，其中底层包含实际的数据点。中间层创建捷径以加速搜索。执行搜索时，HNSW从顶层的一个随机节点开始，向目标导航。当无法再接近时，它会移动到下一层，直到到达底层。在上层中的每一步都可能覆盖数据空间中的很大距离，而在下层中的每一步则优化搜索质量。
  • FAISS (Facebook AI相似性搜索)：它基于一个假设，即在多维空间中，节点之间的距离遵循高斯分布，因此应该存在数据点的聚类。FAISS通过将向量空间划分为聚类，然后在聚类内细化量化来应用向量量化。搜索首先通过粗略量化寻找候选聚类，然后通过更精细的量化进一步检查每个聚类。
  • ScaNN (可扩展最近邻)：ScaNN的主要创新是各向异性向量量化。它将数据点 $x_i$ 量化为 $\tilde{x}_i$，使得内积 $\langle q, x_i \rangle$ 尽可能接近原始距离 $\angle q, \tilde{x}_i$，而不是选择最近的量化质心点。

在 ann-benchmarks.com 查看更多 MIPS 算法及其性能对比。

组件三：工具使用#

工具使用是人类一个显著且独特的特征。我们创造、改造和利用外部物品来完成超越我们身体和认知极限的事情。为大型语言模型配备外部工具可以显著扩展其能力。

MRKL（Karpas et al. 2022）是“Modular Reasoning, Knowledge and Language”（模块化推理、知识与语言）的缩写，它是一种自主体的神经符号架构。MRKL 系统包含一系列“专家”模块，通用大型语言模型充当路由器，将查询路由到最合适的专家模块。这些模块可以是神经网络的（例如深度学习模型），也可以是符号的（例如数学计算器、货币转换器、天气 API）。

他们进行了一项微调大型语言模型以调用计算器的实验，使用算术作为测试案例。实验表明，解决口头数学问题比解决明确表述的数学问题更困难，因为大型语言模型（7B Jurassic1-large 模型）无法可靠地提取基本运算的正确参数。这些结果表明，当外部符号工具能够可靠工作时，知道何时以及如何使用这些工具至关重要，而这取决于大型语言模型的能力。

无论是 TALM（工具增强语言模型；Parisi 等人，2022）还是 Toolformer（Schick 等人，2023），都是通过微调一个语言模型，让它学会使用外部工具 API。数据集的扩展取决于新添加的 API 调用标注能否提升模型输出的质量。更多细节请参阅《提示工程》中的 “外部 API”章节。

ChatGPT 的 插件 和 OpenAI API 的 函数调用 功能，是大型语言模型在实践中成功融入工具使用能力的绝佳范例。工具 API 的集合可以由其他开发者提供（如插件模式），也可以自行定义（如函数调用模式）。

HuggingGPT（Shen 等人，2023）是一个框架，它利用 ChatGPT 作为任务规划器，根据模型描述从 HuggingFace 平台选择合适的模型，并基于执行结果汇总响应。

该系统包含四个阶段：

(1) 任务规划：语言模型充当大脑，将用户的请求解析为多个任务。每个任务都关联四个属性：任务类型、ID、依赖关系和参数。他们使用少样本示例来引导语言模型进行任务解析和规划。

指令：

AI 助手可以将用户输入解析为多个任务：[{"task": task, "id", task_id, "dep": dependency_task_ids, "args": {"text": text, "image": URL, "audio": URL, "video": URL}}]。其中 "dep" 字段表示当前任务所依赖的前一个任务的 ID。特殊标签 "-task_id" 指代 ID 为 task_id 的依赖任务中生成的文本、图像、音频和视频。任务必须从以下选项中选择：{{ 可用任务列表 }}。任务之间存在逻辑关系，请注意它们的顺序。如果无法解析用户输入，你需要回复空 JSON。以下是几个供你参考的案例：{{ 示例 }}。聊天记录记录为 {{ 聊天历史 }}。你可以从聊天历史中找到用户提到的资源路径，用于你的任务规划。

(2) 模型选择：LLM 将任务分配给专家模型，请求被构造成多选题形式。LLM 会被提供一个模型列表供选择。由于上下文长度有限，需要进行基于任务类型的筛选。

指令：

根据用户请求和调用命令，AI 助手帮助用户从模型列表中选择一个合适的模型来处理用户请求。AI 助手只需输出最合适模型的 ID。输出必须采用严格的 JSON 格式："id": "id", "reason": "你选择的详细理由"。我们为你提供了一个模型列表供选择 {{ 候选模型 }}。请从列表中选择一个模型。

(3) 任务执行：专家模型执行特定任务并记录结果。

指令：

根据输入和推理结果，AI 助手需要描述过程和结果。前面的阶段可以组织为 - 用户输入：{{ 用户输入 }}，任务规划：{{ 任务 }}，模型选择：{{ 模型分配 }}，任务执行：{{ 预测 }}。你必须首先直接回答用户的问题。然后以第一人称向用户描述任务过程，展示你的分析和模型推理结果。如果推理结果包含文件路径，必须告诉用户完整的文件路径。

(4) 响应生成：LLM 接收执行结果并向用户提供总结性回复。

要将 HuggingGPT 投入实际应用，需要解决几个挑战：(1) 效率提升是必要的，因为 LLM 推理轮次与其他模型的交互都会拖慢整体流程；(2) 它依赖长上下文窗口来处理复杂的任务内容；(3) 需要改进 LLM 输出和外部模型服务的稳定性。

API-Bank (Li et al. 2023) 是一个用于评估工具增强型 LLM 性能的基准测试。它包含 53 个常用 API 工具、完整的工具增强型 LLM 工作流程，以及 264 个涉及 568 次 API 调用的标注对话。API 的选择相当多样化，包括搜索引擎、计算器、日历查询、智能家居控制、日程管理、健康数据管理、账户认证流程等。由于 API 数量众多，LLM 首先需要通过 API 搜索引擎找到合适的 API 进行调用，然后使用相应的文档来完成调用。

在 API-Bank 的工作流程中，LLM 需要做出多项决策，我们可以在每个步骤评估这些决策的准确性。决策包括：

  1. 是否需要调用 API。
  2. 识别要调用的正确 API：如果不够理想，LLM 需要迭代修改 API 输入（例如为搜索引擎 API 决定搜索关键词）。
  3. 基于 API 结果做出响应：如果结果不满意，模型可以选择优化后再次调用。

该基准测试从三个层次评估代理的工具使用能力：

  • 第一层次评估调用 API的能力。给定 API 的描述，模型需要判断是否调用给定 API、正确调用 API，并对 API 返回做出适当响应。
  • 第二层次考察检索 API的能力。模型需要搜索可能解决用户需求的 API，并通过阅读文档学习如何使用它们。
  • 第三层次评估超越检索和调用的 API 规划能力。面对模糊的用户请求（如安排团队会议、预订旅行中的航班/酒店/餐厅），模型可能需要进行多次 API 调用来解决问题。

案例研究#

科学发现代理#

ChemCrow (Bran et al. 2023) 是一个领域内的典型案例，它将大型语言模型与13个专家设计的工具相结合，用于完成有机合成、药物发现和材料设计等任务。该工作流在 LangChain 中实现，反映了先前在 ReAct 和 MRKLs 中描述的内容，并将思维链推理与任务相关的工具相结合：

  • LLM 会获得一个工具列表，包含它们的用途描述以及预期的输入/输出详情。
  • 随后，它会根据指令在必要时使用提供的工具来回答用户给出的提示。该指令建议模型遵循 ReAct 格式——思考, 行动, 行动输入, 观察。

一个有趣的发现是，虽然基于 LLM 的评估得出 GPT-4 和 ChemCrow 的表现几乎相当，但专家进行的人工评估（侧重于解决方案的完成度和化学正确性）显示，ChemCrow 以较大优势优于 GPT-4。这表明，在需要深厚专业知识的领域使用 LLM 来评估自身性能可能存在潜在问题。专业知识的缺乏可能导致 LLM 无法认识到自身的缺陷，因而无法很好地判断任务结果的正确性。

Boiko et al. (2023) 也研究了用于科学发现的 LLM 赋能智能体，以处理复杂科学实验的自主设计、规划和执行。该智能体可以使用工具浏览互联网、阅读文档、执行代码、调用机器人实验 API 并利用其他 LLM。

例如，当被要求 "开发一种新型抗癌药物" 时，模型提出了以下推理步骤：

  1. 查询了当前抗癌药物发现的趋势；
  2. 选择了一个靶点；
  3. 请求了针对这些化合物的分子骨架；
  4. 一旦化合物被确定，模型便尝试对其进行合成。

他们还讨论了相关风险，特别是涉及非法药物和生物武器的情况。他们开发了一个包含已知化学战剂列表的测试集，并要求智能体合成这些物质。在 11 个请求中，有 4 个（36%）被接受并获得了合成方案，智能体还尝试查阅文档以执行该流程。其余 7 个请求被拒绝，在这 7 个被拒绝的案例中，有 5 个是在网络搜索后发生的，另外 2 个则仅基于提示内容被拒绝。

生成式智能体模拟#

生成式智能体 (Park, et al. 2023) 是一个非常有趣的实验，其中25个虚拟角色，每个都由一个基于大语言模型的智能体控制，在一个受《模拟人生》启发的沙盒环境中生活互动。生成式智能体能为交互式应用创造出逼真的人类行为模拟。

生成式智能体的设计将大语言模型与记忆、规划和反思机制相结合，使智能体能够基于过往经验做出行为，并与其他智能体互动。

  • 记忆流：是一个长期记忆模块（外部数据库），用自然语言记录智能体全面的经历列表。
    • 每个元素都是一个观察，即由智能体直接提供的事件。 - 智能体间的通信可以触发新的自然语言表述。
  • 检索模型：根据相关性、时效性和重要性，将相关上下文呈现给智能体，以指导其行为。
    • 时效性：近期事件得分更高
    • 重要性：区分日常记忆与核心记忆。直接询问语言模型。
    • 相关性：基于与当前情况/查询的相关程度。
  • 反思机制：随时间将记忆综合成更高层次的推论，并指导智能体未来的行为。它们是过去事件的高级总结 (<- 注意这与上文提到的自我反思有所不同)
    • 使用最近的100个观察结果提示语言模型，让其根据一组观察/陈述生成3个最显著的高层次问题，然后让语言模型回答这些问题。
  • 规划与反应：将反思结果和环境信息转化为行动
    • 规划本质上是为了在当下和未来优化行为的可信度。
    • 提示模板：{智能体X的介绍}.以下是X今天的粗略计划：1)
    • 智能体之间的关系以及一个智能体对另一个智能体的观察都会被纳入规划和反应的考量。
    • 环境信息以树状结构呈现。

这个有趣的模拟催生了诸多涌现式的社会行为，例如信息传播、关系记忆（比如两个智能体会延续对话话题）以及社交活动的协调（比如举办派对并邀请许多人）。

挑战#

在了解了构建以大语言模型（LLM）为核心的智能体的关键理念和演示后，我开始看到一些常见的局限性：

  • 有限的上下文长度：受限的上下文容量限制了历史信息、详细指令、API调用上下文和响应的包含。系统设计必须在这种有限的通信带宽下工作，而像自我反思这样的机制，如果能拥有长或无限的上下文窗口，将能从过去的错误中学习到更多。尽管向量存储和检索可以访问更大的知识库，但它们的表征能力不如完整的注意力机制强大。

  • 长期规划和任务分解的挑战：在漫长的历史中进行规划并有效地探索解决方案空间仍然具有挑战性。当面对意外错误时，大语言模型难以调整计划，这使得它们相比通过试错学习的人类来说，鲁棒性较差。

  • 自然语言接口的可靠性：当前的智能体系统依赖自然语言作为大语言模型与内存、工具等外部组件之间的接口。然而，模型输出的可靠性值得怀疑，因为大语言模型可能会出现格式错误，并偶尔表现出叛逆行为（例如，拒绝遵循指令）。因此，许多智能体演示代码都专注于解析模型的输出。
